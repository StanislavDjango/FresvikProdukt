# Стандарты профессионального сайта (2026)

Ниже — практичный чек‑лист, который реально отличает «обычный сайт» от «профессионального».  
Два набора: для **Python/Django + React + Vite + Docker** и для **PHP‑стека**.

---

## 1) Python + Django + React + Vite + Docker

### Обязательный минимум (то, без чего проект выглядит слабее)
- **API v1 + чёткие контракты** (DRF, сериализаторы без магии, enum/nullable).
- **OpenAPI/Swagger** + автогенерация **TypeScript** типов.
- **TypeScript на фронте** — сейчас это стандарт. Без TS проект воспринимается «ниже рынка».
- **Единый API‑клиент** (axios) + обработка ошибок.
- **React Query** для кеша/рефетча/стейтов загрузки.
- **Линтеры/форматтеры** (ESLint + Prettier).
- **Dev/Prod разделение** (Vite dev отдельно, prod — dist + nginx).
- **ErrorBoundary** + базовые логи.
- **README + .env.example** (как запускать, переменные, dev/prod).

### Рекомендовано (делает проект «взрослым»)
- **Миграции и данные**: фикстуры/seed.
- **Тесты**: минимум 1–2 smoke‑теста API.
- **CI/CD**: сборка и тесты при push.
- **Безопасность**: CORS, CSRF, rate limiting, secure headers.
- **Наблюдаемость**: structured logs, централизованный лог.
- **Кэширование**: Redis (если есть нагрузка/частые запросы).

### Опционально по ситуации
- Auth (JWT/Session) — только если реально есть личные кабинеты.
- Очереди (Celery) — если есть фоновые задачи.

---

## 2) PHP‑стек (по современным стандартам)

### Обязательный минимум
- **Фреймворк**: Laravel / Symfony (голый PHP — редкий случай).
- **Типизация и анализ**: PHPStan или Psalm.
- **Стиль**: PHP‑CS‑Fixer.
- **API v1 + OpenAPI/Swagger** (контракты обязательно).
- **TypeScript на фронте** + автогенерация типов из схемы.
- **Единый API‑клиент** + обработка ошибок.
- **Тесты**: Pest / PHPUnit (хотя бы базовые).
- **Dev/Prod разделение**, Docker‑образы.
- **README + .env.example**.

### Рекомендовано
- **Кэш**: Redis.
- **Очереди**: Laravel Queue / Horizon.
- **Логи**: структурированные + централизованные.
- **CI/CD**: тесты + линтер при push.

---

## Почему без TypeScript «сейчас не классно»
TypeScript — это не «мода», а **страховка**:
- контракты не разъезжаются,
- IDE подсказывает корректно,
- меньше багов на проде,
- быстрее разработка.

В 2026 году **проект без TS** воспринимается как «быстро собранный», а не как «профессиональный».
